# v0.17.0 — строгая проверка Trino aliases и reserved keywords

## Статус анализа

Проверено 24 сентября 2026 года по Trino 483, текущей документации Trino,
`plan/reserved_keywords_sql.md`, `sqlparser-rs 0.62.0` и публичному API
`trino-sql-validator 0.16.0`.

Реализовано в `trino-sql-validator 0.17.0`. Перед реализацией уточнены две
границы плана: `is_column_alias` нельзя использовать для строгого reserved
filter, потому что `sqlparser-rs` вызывает его также при разборе projection
commas; конструкция `identifier 'value'` является Trino typed literal, а не
implicit single-quoted alias.

Список из 83 reserved keywords в `plan/reserved_keywords_sql.md` полный и
побайтно совпадает со списком Trino 483 и текущим `master`. Правила
`selectItem` и `aliasedRelation` действительно требуют `identifier`, поэтому
ни explicit `AS`, ни implicit alias не разрешают unquoted reserved word.

## Найденные расхождения

### 1. Reserved aliases ошибочно принимаются

Exhaustive-проверка всех 83 слов дала следующие false accepts:

| Контекст | Принято валидатором | Ожидание Trino |
| --- | ---: | --- |
| `SELECT 1 AS <word>` | 83/83 | 0/83 |
| `SELECT 1 <word>` | 63/83 | 0/83 |
| `FROM orders AS <word>` | 83/83 | 0/83 |
| `FROM orders <word>` | 61/83 | 0/83 |
| `FROM (SELECT 1) AS <word>` | 83/83 | 0/83 |
| `FROM (SELECT 1) <word>` | 61/83 | 0/83 |
| CTE column alias `<word>` | 83/83 | 0/83 |
| relation alias column `<word>` | 83/83 | 0/83 |

Например, сейчас валидны `SELECT 1 AS SELECT`,
`SELECT * FROM orders AS GROUP` и
`WITH t(WHERE) AS (SELECT 1) SELECT * FROM t`. Они должны возвращать
`ValidationResult(valid=False, ...)`, а не warning: Trino считает это
синтаксической ошибкой.

Корень проблемы — `TrinoDialect` делегирует `is_select_item_alias`,
`is_column_alias`, `is_table_alias` и `is_table_factor_alias` в
`GenericDialect`. Default hooks безусловно разрешают keyword после explicit
`AS`, а generic reserved-наборы не совпадают с Trino. Прямые вызовы
`sqlparser-rs::parse_identifier()` также принимают любой `Token::Word`, поэтому
одних alias hooks недостаточно для CTE names и parenthesized alias columns.

### 2. Single-quoted aliases ошибочно принимаются

Все проверенные формы с `'group'` принимаются: projection alias, table alias и
subquery alias, с `AS` и без него. Trino допускает для delimited identifiers
только двойные кавычки. Причина — обратная совместимость
`sqlparser-rs::parse_optional_alias_inner`, которая принимает
`Token::SingleQuotedString` как alias независимо от dialect.

### 3. Часть valid non-reserved aliases ошибочно отклоняется

Trino 483 содержит 230 token alternatives в `nonReserved`. Текущая generic
alias policy создаёт false rejects:

- implicit projection aliases: `ANALYZE`, `EXPLAIN`, `FETCH`, `LATERAL`,
  `LIMIT`, `MATCH`, `OFFSET`, `RETURNING`, `VIEW`;
- implicit table/subquery aliases: `ANALYZE`, `ARRAY`, `EXPLAIN`, `FETCH`,
  `FORMAT`, `LATERAL`, `LIMIT`, `MATCH_RECOGNIZE`, `OFFSET`, `OUTPUT`,
  `PARTITION`, `PIVOT`, `RETURNING`, `SET`, `START`, `TABLESAMPLE`, `VIEW`,
  `WINDOW`;
- explicit table/subquery alias `TABLESAMPLE`.

Это затрагивает контракт v0.16.0: `PARTITION` корректно выдаёт `AliasWarning`
как projection alias и explicit relation alias, но implicit table/subquery
alias сейчас invalid.

При разрешении implicit aliases нельзя просто принимать любой `nonReserved`:
слова `LIMIT`, `OFFSET`, `FETCH`, `WINDOW`, `TABLESAMPLE`, `PIVOT` и другие
также начинают реальные clauses. Нужен context/lookahead, чтобы, например,
`SELECT 1 LIMIT 5` оставался clause, а `SELECT 1 LIMIT` мог быть alias согласно
Trino grammar.

### 4. Методологические числа в исходном документе требуют исправления

Список 83 слов и его SHA-256 корректны. Однако утверждение про 312 bare-word
tokens и 229 значений `nonReserved` не соответствует правилам
`SqlKeywords`: его regex принимает только token literals `[A-Z_]+`.

Статический аудит grammar даёт 309 именованных lexer rules с одиночным
uppercase literal плюс implicit literal `SKIP`, то есть 310 bare-word keyword
tokens. Из 230 alternatives правила `nonReserved` три (`UTF8`, `UTF16`,
`UTF32`) содержат цифры и не входят в множество `SqlKeywords`, поэтому
сопоставимое число non-reserved keyword literals — 227. Разность остаётся
равна документированным 83. Перед правкой текста нужно подтвердить числа
запуском самого `SqlKeywords`/`ReservedIdentifiers` из pinned checkout, чтобы
не подменять runtime Vocabulary простым regex по исходнику.

## Целевой контракт

1. Для `dialect="trino"` любое из 83 reserved words как unquoted alias даёт
   invalid result с позицией самого alias и без warnings.
2. Запрет относится только к unquoted reserved words. Reserved word в двойных
   кавычках остаётся допустимым Trino delimited identifier в любой позиции,
   где grammar ожидает identifier. Это включает DDL object names, составные
   имена объектов, projection/table aliases, имена и ссылки на колонки и
   qualifiers. Например, `SELECT 1 AS "where"` валиден, тогда как
   `SELECT 1 AS where` невалиден. Также валидны `dwh_team."FROM"`,
   `AS "FROM"`, `"FROM"."ALTER"` и `SELECT "alter", "where", "from",
   "drop" FROM my_schema.table_name`. Reserved-проверка не должна зависеть от
   регистра текста внутри двойных кавычек и не должна выдавать для такого
   identifier `AliasWarning`.
3. Single-quoted и backquoted aliases невалидны.
4. Все Trino `nonReserved` identifiers допустимы как aliases там, где grammar
   не выбирает одноимённый clause; explicit `AS` всегда снимает такую
   неоднозначность.
5. `ALL`, `OVER`, `PARTITION`, `RETURN`, `AT` остаются валидными unquoted
   aliases и получают `AliasWarning`; quoted forms не получают warning.
6. `AT TIME ZONE` и `AT LOCAL`, а также реальные `LIMIT`, `OFFSET`, `FETCH`,
   `WINDOW`, `TABLESAMPLE`, `PIVOT` и `MATCH_RECOGNIZE` clauses не меняют
   поведение.
7. `hive` и `generic` сохраняют текущую policy своего dialect.

## План реализации

- [x] Добавить единый case-insensitive source of truth для 83 Trino reserved
  aliases с provenance на Trino 483; не смешивать его с пятью advisory aliases.
- [x] Переопределить Trino alias hooks для projection и table factors:
  explicit aliases должны отклонять reserved words, а implicit aliases должны
  различать identifier и одноимённый clause по lookahead.
- [x] Добавить AST/token validation для alias positions, которые проходят через
  безусловный `parse_identifier`: CTE name/columns, relation alias columns и
  остальные поддерживаемые Trino grammar aliases. Проверку ограничить именно
  alias positions: нельзя глобально запрещать `Ident` по тексту, иначе
  корректные DDL object names, aliases и обращения к колонкам вроде `"where"`
  станут false rejects. В alias positions учитывать quote style до сравнения со
  списком reserved words: любой double-quoted вариант должен миновать запрет.
- [x] Явно отклонять `Ident`/alias с single-quote quote style; double-quoted
  aliases оставить валидными. Не ослаблять существующий запрет backticks.
- [x] Сохранить `AliasWarning` только для пяти valid contextual aliases и
  расширить его regression coverage на implicit relation/subquery
  `PARTITION`.
- [x] Не делать blanket token rewrite reserved words в `NoKeyword`: это
  превратит реальные clauses/operators в identifiers и создаст новые false
  accepts.

## Критерии готовности

- Ноль false accepts в exhaustive matrix 83 reserved words.
- Ноль false rejects в double-quoted matrix.
- Double-quoted reserved identifiers остаются валидны во всех разрешённых
  grammar identifier positions, включая DDL object names, projection/table
  aliases, qualified object names, quoted table qualifiers и qualified column
  references; bad-practice характер таких имён не влияет на syntax validity.
- Ноль известных false rejects в `nonReserved` alias matrix, включая implicit
  `PARTITION` и explicit `TABLESAMPLE`.
- Reserved aliases никогда не превращаются в `AliasWarning`: результат invalid.
- Ошибки содержат стабильные line/column исходного alias.
- Generic/Hive behavior и temporal/clause syntax не имеют регрессий.
