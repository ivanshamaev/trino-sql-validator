# v0.8.0 Plan: reject empty Trino FROM relations

## Analysis

The validator accepted `SELECT a FROM WHERE` because sqlparser's generic
fallback can interpret a clause keyword as an unquoted table name in the first
FROM position. The same false positive occurred for `GROUP` and `ORDER`. This
is a syntax-level gap, not semantic table validation: the validator still does
not resolve tables, columns, or schemas.

## Implementation

- Add a Trino-only token-aware preflight before AST parsing.
- Ignore whitespace and comments, then reject `FROM` followed immediately by a
  clause keyword such as `WHERE`, `GROUP`, `ORDER`, `HAVING`, `LIMIT`, `OFFSET`,
  `UNION`, `EXCEPT`, or `INTERSECT`.
- Keep quoted identifiers such as `FROM "where"` valid.
- Leave Hive and Generic dialect behavior unchanged.
- Add inline regression tests for invalid empty FROM relations and a valid
  quoted keyword identifier.

The preflight intentionally does not attempt semantic validation. It is a
small correction for a parser ambiguity and does not replace execution against
Trino or a future Trino grammar.

## Verification

Run `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`,
`pytest -q`, `ruff check .`, and `mypy python/trino_sql_validator`.
