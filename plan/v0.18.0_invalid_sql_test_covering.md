# v0.18.0 — покрытие заведомо невалидного Trino SQL

## Статус

План подготовлен 25 сентября 2026 года для `trino-sql-validator 0.17.0` и
реализован в `0.18.0` в тот же день. Валидатор отклоняет все 236 независимых
fixture cases; полный positive fixture corpus, focused regressions и pinned
Trino 483 audit проходят без новых regressions.

Baseline upstream audit не изменялся: после реализации улучшены три ранее
разрешенных positive-statement mismatch, а итог остается в допустимых границах
baseline — 479/484 statements, 231/238 expressions, 68/68 types и 23/23 direct
negative statements.

## Post-review: дополнительные исправления реализации

Повторное code review после первичной реализации выявило, что прохождение
236-case fixture и pinned audit не покрывает несколько соседних конструкций.
Все перечисленные ниже замечания закрыты повторной доработкой и regression
tests:

1. `validate_cte_as` проверяет только первый `namedQuery` после `WITH` и
   пропускает отсутствие `AS` у второго и последующих CTE.
2. Reserved identifiers проверяются не во всех AST-ролях. В частности,
   ошибочно принимаются unquoted reserved names у некоторых DDL objects,
   prepared statements, routine parameters, row fields, `JOIN USING` и
   одночастных обычных function names. Их double-quoted формы должны оставаться
   допустимыми.
3. Проверка пяти parser-special functions теряет `RUNNING`/`FINAL` до AST и
   слишком широко разрешает `qualified.*` среди нескольких arguments.
4. Token guard для `MATCH_RECOGNIZE MEASURES` принимает non-reserved слова
   `AFTER`, `ALL`, `ONE`, `PATTERN`, `SUBSET`, `DEFINE` за границы clause даже
   внутри валидного measure expression.
5. Новые AST errors создаются без source location, а independent-negative test
   не контролирует обещанный positional contract.

### V018-R01 — CTE list и MATCH_RECOGNIZE structure

- [x] Обойти каждый top-level элемент CTE list с учетом optional column list,
  nesting и нескольких CTE; для каждого query body требовать `AS`.
- [x] Перенести проверку `MEASURES expression AS identifier` на распарсенный
  `TableFactor::MatchRecognize` и source span alias, чтобы non-reserved clause
  words оставались допустимы внутри expression.
- [x] Добавить regressions для второго/третьего и nested CTE, quoted column list,
  нескольких measures и каждого из шести non-reserved слов в expression.

### V018-R02 — полнота reserved identifier roles

- [x] Расширить AST validation для DDL object names, prepared statement names,
  routine names/parameters, row fields, `JOIN USING` и одночастных function
  names, не превращая самостоятельные keyword expressions в identifiers.
- [x] Разрешать double-quoted reserved identifiers во всех новых ролях и
  сохранять parser-special и прочие выделенные grammar forms.
- [x] Добавить paired invalid-unquoted/valid-quoted matrices для каждой роли,
  а также nested row/function declarations.

### V018-R03 — точный parser-special function contract

- [x] Не удалять row-pattern processing mode перед проверкой `IF`, `NULLIF`,
  `COALESCE`, `TRY`, `FORMAT`; `RUNNING` и `FINAL` для них должны быть invalid.
- [x] Разрешать `label.*` только как единственный argument; из пяти специальных
  форм по arity это сохраняет допустимый `TRY(label.*)`.
- [x] Расширить negative matrix processing modes и mixed wildcard arguments,
  сохранив positive ordinary pattern functions и `TRY(label.*)`.

### V018-R04 — located errors и повторный release gate

- [x] Формировать новые AST errors из source spans/attached tokens и проверять
  line/column для всех случаев, где offending token доступен.
- [x] Усилить 236-case contract явной проверкой положительных line/column и
  документированным списком только тех legacy parser errors, для которых
  `sqlparser-rs` не возвращает location.
- [x] Повторить все quality gates, adversarial cases и pinned Trino 483 audit;
  затем обновить этот раздел фактическим результатом code review.

### Итог post-review

Повторный review не выявил незакрытых замечаний в согласованном scope. Все 236
negative fixture cases отклоняются отдельно; 234 ошибки содержат положительные
`line`/`column`. Исключения зафиксированы по индексам 097 и 202: это два legacy
`sqlparser-rs` errors без source location. Парные unquoted/quoted regressions,
включая nested ROW/function declarations, проходят.

После свежего `maturin develop` проходят 82 Rust unit tests и 4556 pytest tests,
`fmt`, `clippy -D warnings`, `ruff`, `mypy`, оба generated-catalog checks и
pinned Trino 483 audit. Audit остается в baseline: 479/484 positive statements,
231/238 expressions, 68/68 types и 23/23 direct negative statements.

## Источники истины и методика

Синтаксический oracle для этого файла — официальный
`io.trino:trino-parser:483`, собранный из commit
`50b0b50b75abd47f830b7805ee1b51716eb4065e`. Каждый fixture case передавался
отдельно в `SqlParser.createStatement()`. Один последний `;`, используемый в
файле как разделитель case, удалялся только для вызова Java parser. Запросы не
объединялись в multi-statement input и не выполнялись на coordinator.

Проверка опирается на:

- grammar Trino 483:
  <https://github.com/trinodb/trino/blob/483/core/trino-grammar/src/main/antlr4/io/trino/grammar/sql/SqlBase.g4>;
- parser-time проверки `AstBuilder` Trino 483:
  <https://github.com/trinodb/trino/blob/483/core/trino-parser/src/main/java/io/trino/sql/parser/AstBuilder.java>;
- синтаксис `SELECT`, включая необязательный `FROM` и `FETCH`:
  <https://trino.io/docs/current/sql/select.html>;
- синтаксис scalar и row forms `VALUES`:
  <https://trino.io/docs/current/sql/values.html>;
- синтаксис `MATCH_RECOGNIZE`, включая эквивалентность `{,}` и `*`:
  <https://trino.io/docs/current/sql/match-recognize.html>.

Это именно parser-level проверка. Разрешение имен колонок и таблиц, типизация,
существование объектов, права, connector capabilities и обычная проверка
перегрузок функций в scope не входят.

## Результат аудита fixture

После разбиения по независимым блокам файл содержит ровно 236 cases.

| Состояние | Trino 483 | validator 0.17.0 |
| --- | ---: | ---: |
| До исправления действительно валидных cases | 226 invalid, 10 valid | 194 rejected, 42 accepted |
| После исправления fixture | 236 invalid, 0 valid | 201 rejected, 35 accepted |

Таким образом:

- текущая библиотека уже корректно покрывает 201/236, или 85,2%, итогового
  negative corpus;
- 35/236, или 14,8%, являются подтвержденными false accepts;
- все 236 итоговых cases отклоняются официальным Trino parser 483;
- warnings для всех 35 false accepts сейчас пусты, то есть проблема именно в
  ошибочном `valid=True`, а не в классификации warning.

### Исправленные валидные запросы

В первоначальном файле было 10 parser-valid конструкций. Они заменены на
ближайшие однозначно невалидные формы без изменения общего числа cases.

| Case | Было | Почему это валидно в Trino 483 | Стало |
| ---: | --- | --- | --- |
| 036 | `SELECT orderkey, custkey WHERE orderkey = 1` | `FROM` в `querySpecification` необязателен; неизвестные имена — семантика | `SELECT orderkey, custkey WHERE` |
| 065 | закрытый многострочный `'unterminated\nstring'` | перевод строки допустим внутри обычного Trino string literal | действительно незакрытый многострочный literal |
| 101 | `row_number() OVER FROM orders` | `OVER` разбирается как допустимый implicit alias, после него начинается `FROM` | `row_number() OVER (ORDER BY)` |
| 104 | `ROWS 2 PRECEDING` | это допустимая сокращенная `frameExtent` без `BETWEEN` | `ROWS 2` без направления границы |
| 135 | `VALUES 1, 'O', 100.0` | это три scalar rows; скобки нужны только для многоколоночной row | между первыми scalar rows удалена запятая |
| 161 | `FETCH NEXT ROWS ONLY` | `count` опционален и по умолчанию равен 1 | `FETCH NEXT 5 ONLY`, без `ROW/ROWS` |
| 171 | `PATTERN (a{,})` | `{,}` документирован как эквивалент `*` | quantifier `a{1,2,3}` с тремя границами |
| 203 | `INTERVAL '3'` | parser принимает это через `identifier string` как type constructor | `INTERVAL '3' TO DAY`, без начальной interval unit |
| 205 | `(ARRAY['a'], ARRAY[1])` | это корректный row constructor | `MAP(...)` без запятой между аргументами |
| 222 | `SELECT count FROM orders` | `COUNT` — non-reserved identifier и может быть именем колонки | незакрытый `count(` |

Два дополнительных positive regressions обнаружены при этой проверке:

1. v0.17.0 ошибочно отклоняет допустимый `PATTERN (a{,})`; v0.18.0 должен
   принять `{,}` и `{,}?` только внутри row pattern.
2. v0.17.0 принимает `row_number() OVER FROM orders`, но не выдает ожидаемый
   `AliasWarning` для implicit alias `OVER`. Parser path не должен принимать
   reserved `FROM` за имя окна.

Остальные восемь исходных valid cases уже принимаются библиотекой и нужны как
positive neighbors, чтобы исправление false accepts не стало blanket reject.

## Полный перечень 35 false accepts

### 1. Query, relation и identifier grammar — 10 cases

| Cases | Сейчас ошибочно принимается | Требование Trino |
| --- | --- | --- |
| 001, 002 | trailing comma перед `FROM` | `selectItem (',' selectItem)*` не допускает пустой последний item |
| 042 | обычный `JOIN` без `ON`/`USING` | любой не-`CROSS` и не-`NATURAL` join требует `joinCriteria` |
| 076–079 | `select`, `where`, `from`, `group`/`order` как unquoted object/column names | reserved word не является `identifier`; двойные кавычки остаются валидны |
| 081 | `WITH big (SELECT ...)` без `AS` | `namedQuery` требует `name ... AS '(' query ')'` |
| 098 | `USING (o.custkey)` | `USING` принимает список простых `identifier`, не qualified names |
| 227 | `SELECT order-key` | `ORDER` — reserved token, поэтому выражение нельзя трактовать как вычитание identifiers |

Корни расхождений различаются. `sqlparser-rs` разрешает trailing commas через
dialect capability, допускает `JoinConstraint::None`, хранит элементы `USING`
как `ObjectName`, а `parse_identifier()` принимает любой `Token::Word`.
Alias-only проверка v0.17.0 поэтому не закрывает object names, column names и
expression identifiers.

### 2. Parser-special functions — 3 cases

| Case | Сейчас ошибочно принимается | Parser-time contract Trino |
| ---: | --- | --- |
| 116 | `IF(condition)` | ровно 2 или 3 positional arguments |
| 117 | `coalesce()` | не меньше 2 arguments |
| 118 | `nullif(a, b, c)` | ровно 2 arguments |

Это не начало общей semantic проверки arity. `IF`, `NULLIF`, `COALESCE`,
`TRY` и `FORMAT` обрабатываются специально в официальном `AstBuilder` и
вызывают `ParsingException` до semantic analysis. Реализация должна повторить
весь parser-special набор из пяти имен, включая запрет `DISTINCT`, named args,
`FILTER`, `OVER`, null treatment и row-pattern processing mode, где он запрещен
официальным parser.

### 3. Обязательные DML keywords — 3 cases

| Case | Сейчас ошибочно принимается | Требование Trino |
| ---: | --- | --- |
| 133 | `INSERT orders ...` | обязательно `INSERT INTO` |
| 139 | `DELETE orders ...` | обязательно `DELETE FROM` |
| 144 | `TRUNCATE orders` | обязательно `TRUNCATE TABLE` |

Нужные признаки уже сохранены AST `sqlparser-rs`: `Insert.into`, вариант
`Delete.from` и `Truncate.table`. Их следует проверять в
`validate_trino_ast`, не искать ключевые слова regex по исходной строке.

### 4. LIMIT/FETCH — 3 cases

| Case | Сейчас ошибочно принимается | Требование Trino |
| ---: | --- | --- |
| 160 | `FETCH FIRST 5` | после optional count обязательны `ROW/ROWS` и `ONLY/WITH TIES` |
| 161 | `FETCH NEXT 5 ONLY` | обязательны `ROW/ROWS` |
| 162 | `LIMIT 10 FETCH ...` | grammar разрешает ровно одну из альтернатив `LIMIT` или `FETCH` |

AST `Fetch` не сохраняет все пропущенные keywords, поэтому одной post-AST
проверки недостаточно. Нужен located-token validator точной Trino shape плюс
AST-проверка взаимного исключения `limit_clause` и `fetch`.

### 5. SQL/JSON и лексический `$` — 2 cases

| Case | Сейчас ошибочно принимается | Требование Trino |
| ---: | --- | --- |
| 163 | `JSON_VALUE(payload)` | `jsonPathInvocation` требует expression, запятую и string path |
| 167 | `json_extract(payload, $.page)` | `$` вне quoted JSON path не является Trino token/expression |

`sqlparser-rs` может представить `$` как generic placeholder. Для Trino такой
placeholder надо отклонять до normalizers; `?` parameter и корректные
dollar-quoted routine bodies должны остаться разрешены. SQL/JSON guard должен
работать только с реальным unquoted `JSON_VALUE`, не со строками, комментариями
или quoted function names.

### 6. MATCH_RECOGNIZE — 1 case

Case 170 содержит `MEASURES match_number() mn` без `AS`. Trino rule
`measureDefinition` — это строго `expression AS identifier`. Generic parser
разрешает implicit alias, поэтому нужен located structural guard внутри
`MATCH_RECOGNIZE`, не глобальный запрет implicit projection aliases.

### 7. PREPARE/EXECUTE family — 2 cases

| Case | Сейчас ошибочно принимается | Требование Trino |
| ---: | --- | --- |
| 174 | `EXECUTE USING 1` | после `EXECUTE` обязательно имя либо специальная форма `EXECUTE IMMEDIATE string` |
| 175 | `DEALLOCATE stmt1` | Trino требует `DEALLOCATE PREPARE identifier` |

`Statement::Execute.name/immediate` и `Statement::Deallocate.prepare` позволяют
проверить это после parse. Одновременно надо сохранить valid формы `EXECUTE
name`, `EXECUTE name USING ...` и `EXECUTE IMMEDIATE '...' USING ...`.

### 8. Пустые statement segments — 3 cases

Cases 186–188 — `SELECT ...;;`, `SELECT ...;;;` и отдельный `;`.

Публичный API проекта намеренно допускает:

- пустую или comments-only строку как valid с `statement_count=0`;
- один terminal `;` после непустого statement;
- несколько непустых statements, разделенных одним top-level `;`;
- `;` внутри SQL routine body, строк и комментариев.

v0.18.0 должен отклонять только пустой top-level segment: delimiter-only input,
два соседних delimiters и пустой segment между statements. Это сохраняет
`validate("SELECT 1;")`, multi-statement API и routine parsing. Проверка должна
использовать тот же quote/comment/group/routine-aware token model, что и
statement boundaries, а не `str.contains(";;")`.

### 9. Операторы и literals — 3 cases

| Case | Сейчас ошибочно принимается | Требование Trino |
| ---: | --- | --- |
| 064 | `X'ABC'` | binary literal должен содержать четное число hex digits |
| 197 | `orderkey == 1` | Trino comparison grammar знает `=`, но не `==` |
| 203 | `INTERVAL '3' TO DAY` | после `TO` отсутствует начальная interval unit |

`Token::DoubleEq` надо отклонять только в Trino dialect. Для binary literal
следует считать значащие hex digits по правилам Trino, включая допустимые
пробелы. Interval guard не должен запрещать parser-valid generic type
constructor `INTERVAL '3'`.

### 10. Остальные clause/statement forms — 5 cases

| Case | Сейчас ошибочно принимается | Требование Trino |
| ---: | --- | --- |
| 209 | `orders WITH ORDINALITY` | `WITH ORDINALITY` разрешено только после `UNNEST(...)` |
| 210 | `EXPLAIN (TYPE UNKNOWN)` | TYPE: только `LOGICAL`, `DISTRIBUTED`, `VALIDATE`, `IO` |
| 211 | bare `SHOW` | после `SHOW` обязателен один из поддержанных объектов/вариантов |
| 229 | `CURRENT_DATE()` | `CURRENT_DATE` не принимает скобки |
| 230 | `CURRENT_TIMESTAMP(3, 4)` | допустима максимум одна integer precision |

Помимо пяти fixture regressions, для date/time family нужны отдельные
positive/negative matrices для `CURRENT_DATE`, `CURRENT_TIME`,
`CURRENT_TIMESTAMP`, `LOCALTIME` и `LOCALTIMESTAMP`.
