# v0.21.0 — строгая граница `::` в Trino expressions

## Статус

План подготовлен 27 сентября 2026 года для выпущенной версии
`trino-sql-validator 0.20.0`, commit `5894b5b`, и реализован в `0.21.0` в тот
же день. Исходный запрос теперь возвращает located invalid result на `::`, а
валидные Trino static method calls и поведение Generic/Hive сохранены.

Focused oracle corpus из 15 cases в
[`tests/cases/trino_483_v021_double_colon.json`](../tests/cases/trino_483_v021_double_colon.json)
прогнан через
`io.trino:trino-parser:483` на Temurin JRE 25.0.4.1: девять invalid cases
отклонены, шесть positive controls приняты, expected-label mismatches нет.
После свежего `maturin develop` проходят 5 015 pytest cases и 87 Rust tests,
все quality gates и pinned upstream audit.

Цель версии — перестать принимать PostgreSQL-style casts `expression::type`
в режиме `dialect="trino"`, не сломав настоящий Trino syntax для static method
calls вида `qualifiedName::methodName(...)`.

## Подтверждённая проблема

Публичный API `0.20.0` ошибочно возвращал `valid=True`:

```sql
SELECT
   t.date::date
from dwh.table_name t
```

Результат `0.20.0` до исправления:

```text
valid=True, statement_count=1, error=None
```

Та же проблема воспроизводилась для `SELECT x::bigint`,
`SELECT (x)::bigint` и `SELECT '2024-01-01'::date`. Режимы `trino`,
`generic` и `hive` сейчас принимают исходный пример.

В Trino 483 `::` присутствует в `primaryExpression` только в production:

```antlr
qualifiedName '::' methodName '(' (argument (',' argument)*)? ')'
```

Следовательно, исходный пример является parser-level ошибкой: после второго
`date` нет обязательного `(`. Это не semantic/type check.

Положительная граница уже подтверждена сохранённым Trino 483 oracle case
`GE07`:

```sql
SELECT bigint::select(value => 1)
```

Этот запрос и существующие regressions с `bigint::parse(...)` должны остаться
валидными. В частности, `x::decimal(10, 2)` на уровне grammar неотличим от
static method call и не должен отклоняться только потому, что автор мог
подразумевать PostgreSQL cast.

Источники истины:

- Trino 483 `primaryExpression/staticMethodCall` и `methodName`:
  <https://github.com/trinodb/trino/blob/483/core/trino-grammar/src/main/antlr4/io/trino/grammar/sql/SqlBase.g4#L600-L615>;
- текущая compatibility-нормализация:
  `src/dialects/trino_types.rs::normalize_method_calls`;
- Generic parsing `Token::DoubleColon` как `CastKind::DoubleColon`:
  `sqlparser-rs 0.62.0`, `src/parser/mod.rs::parse_infix`.

При подготовке плана локально были доступны только JDK 11/17. В ходе
реализации focused corpus успешно проверен собранным Trino 483 harness на
временной Temurin JRE 25; Java не добавлена в зависимости проекта.

## Корень расхождения

`TrinoDialect` делегирует большую часть expression grammar в
`GenericDialect`. `sqlparser-rs` без отдельного capability flag всегда
назначает `Token::DoubleColon` postfix precedence и строит
`Expr::Cast { kind: CastKind::DoubleColon, ... }`.

Перед generic parse функция `normalize_method_calls` заменяет `::` на `.`
только для распознанной формы static method call. Нераспознанный `::`
остаётся в token stream, после чего Generic parser принимает его как cast.
Отдельного Trino guard для оставшихся `Token::DoubleColon` сейчас нет.

## План реализации

### V021-01 — строгая token-level проверка

- [x] Сделать обработку `Token::DoubleColon` в
  `normalize_method_calls` fallible либо добавить непосредственно перед ней
  отдельный `validate_trino_static_method_calls`.
- [x] Для каждого `::` разрешать только Trino shape
  `qualifiedName :: methodName (`:
  - слева должна заканчиваться цепочка identifiers, разделённых `.`;
  - receiver не может быть literal, parenthesized expression, subscript,
    dereference от произвольного expression или результат другого call;
  - справа обязателен `methodName`, после которого следующим significant
    token идёт `(`;
  - whitespace, comments, quoted identifiers и keyword method names должны
    сохранять разрешённое grammar-поведение.
- [x] После распознавания оставить существующую token normalization и
  warning extraction для static methods без изменения.
- [x] Любой оставшийся `Token::DoubleColon` отклонять до Generic parse с
  located `ParserError` на позиции `::`, например:
  `Trino '::' is only valid in a static method call`.
- [x] Не вводить глобальный AST-запрет `CastKind::DoubleColon` как основной
  механизм: он даёт менее точный source anchor и проверяет ошибку слишком
  поздно. Допустим defensive assertion, что такой AST не дошёл до успешного
  Trino result.

Для исходного примера ожидается `line=2`, `column=10`,
`statement_count=0`, `warnings=()`.

### V021-02 — regression matrix

- [x] Добавить focused Rust tests для `parse_sql` и public pytest regressions
  в отдельный `tests/test_v021_double_colon.py`.
- [x] Проверить invalid cases:
  - `SELECT t.date::date FROM dwh.table_name t`;
  - `SELECT x::bigint`;
  - `SELECT '2024-01-01'::date`;
  - `SELECT (x)::bigint`;
  - `SELECT x::bigint[]`;
  - incomplete/chained формы `x::`, `x::a::b()`;
  - multiline LF и CRLF с exact operator location.
- [x] Проверить positive neighbors:
  - `SELECT bigint::parse(value => '42')`;
  - qualified receiver `catalog.schema.type_name::method_name()`;
  - quoted receiver/method names;
  - keyword method name `bigint::select(value => 1)`;
  - whitespace/comments вокруг `::`;
  - `x::decimal(10, 2)` как parser-valid static-call shape, независимо от
    возможного намерения автора.
- [x] Сохранить warning contract: неизвестный static method выдаёт
  `FunctionWarning` с исходной позицией; invalid cast-like формы не выдают
  catalog warnings.
- [x] Явно проверить, что `dialect="generic"` и `dialect="hive"` сохраняют
  текущее поведение для `SELECT x::bigint`. Исправление относится только к
  Trino path.
- [x] Добавить multi-statement regression: ошибка во втором statement имеет
  координаты исходного SQL, а публичный результат сохраняет действующий
  invalid-result contract.

## Вне scope

- Общая semantic проверка существования static methods, типов и overloads.
- Запрет всех запросов, внешне похожих на PostgreSQL cast, если они совпадают
  с валидной Trino static-call grammar.
- Изменение Generic/Hive dialect behavior.
- Замена `sqlparser-rs`, добавление Java parser в production или изменение
  публичных tuple/dataclass shapes.

- Исходный запрос возвращает located invalid result на `::`.
- Все cast-like cases без обязательного static method call rejected в Trino.
- Все подтверждённые static method calls остаются valid, с прежними warning
  names и source positions.
