# v0.16.0: contextual alias warnings

## Problem

The validator accepts Trino's non-reserved words as aliases, but gives callers
no indication when an alias is easily confused with surrounding SQL syntax.
The reported examples are `ALL`, `OVER`, `PARTITION`, `RETURN`, and `AT`.

`AT` also had a separate parser defect: every unquoted occurrence was treated
as if it started Trino's temporal operator. As a result, valid aliases such as
`SELECT value AS At` failed with `AT requires TIME ZONE or LOCAL`.

In the Trino 483 grammar, all five words belong to `nonReserved`, so they are
valid unquoted identifiers. They also have contextual SQL meanings, making an
alias such as `SELECT 1 AS partition` legal but easy to misread. The validator
should report an advisory warning rather than a syntax error.

## Intended behavior

- Accept unquoted `AT` in identifier positions, including projection, relation,
  and CTE aliases.
- Emit an `AliasWarning` for an unquoted alias named `ALL`, `OVER`, `PARTITION`,
  `RETURN`, or `AT`, preserving its normalized lowercase name and source line
  and column. The warning must not change `ValidationResult.valid`.
- Do not warn for quoted aliases such as `"At"`.
- Keep `AT TIME ZONE` and `AT LOCAL` working as temporal expressions without an
  alias warning.
- Keep malformed temporal syntax such as `AT TIME` or `AT UTC` invalid.
- Emit alias warnings only for the Trino dialect, consistently with the other
  analytical warnings.

## Implementation plan

- [x] Narrow the `AT LOCAL` compatibility rewrite to expression-operator
  positions and let the parser accept `AT` elsewhere as a non-reserved word.
- [x] Walk successful Trino ASTs for projection, relation, CTE, and alias-column
  identifiers matching the five contextual names; return warning kind `alias`
  through the existing native warning tuple.
- [x] Add the typed public `AliasWarning` model and `ambiguous_aliases`
  convenience property without changing the native tuple shape.
- [x] Add Rust and Python regressions for all five names, case-insensitive
  explicit/implicit aliases, quoted aliases, warning positions, and
  temporal/malformed neighbors.
- [x] Document the advisory warning, bump both package versions to `0.16.0`,
  refresh `Cargo.lock`, and update the changelog.
- [x] Run formatting, linting, type checking, Rust tests, and pytest against a
  freshly rebuilt native extension.

## Compatibility notes

The change deliberately reclassifies a previous false syntax error as a valid
result with a warning. The four-field native warning tuple is unchanged; only a
new warning kind and corresponding Python dataclass are added. Quoting the
alias is the opt-out because it makes the identifier intent explicit.
